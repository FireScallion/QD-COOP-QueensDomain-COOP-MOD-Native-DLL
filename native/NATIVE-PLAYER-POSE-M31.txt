M31 native player poses on QueensDomain Steam build 26496428

The native game thread captures the current possessed local Pawn at up to
20 Hz. Kind 12 uses the existing room nonce and world hash with a 92-byte
packet for Pawn generation, sequence, source time, position, yaw and
velocity. A guest sends an unassigned slot. The host assigns slots 1–3
from the authenticated peer index and relays accepted packets to the
other guests. The host sends slot 0 directly. All participants use the
QDN4-3 Steam transport tag.

Each receiver keeps a bounded clock and transform history for each
remote slot. The native factory spawns an independent SkeletalMeshActor
with collision disabled, the stock Player_FullChar_2026 mesh and the
stock coolPose sequence when available. The root uses preview3's 85-unit
vertical offset. The renderer reuses the actor for movement, replaces it
on a new Pawn generation, hides it after 0.5 s of silence, and destroys
it after 3 s. Room teardown and Steam roster recovery destroy the owned
actors before releasing the old epoch. Player pose code reads the local
Pawn and limits its writes to owned displays.

Build and reproduction

Run Build-EnemyM1.ps1 with a MinGW-w64 C++20 compiler. It verifies player
packet scope, shape and guest slot assignment alongside the existing
native build gates. Build QDNativeWorld.dll from
tests/native_tick_lab/native_world.cpp and adapters/windows/native_tick_bridge.cpp
with the native include directory, -std=c++20 -O2 -static -shared,
-Wl,--exclude-all-symbols, -lbcrypt and -lws2_32.

Use the private station layout in tests/native_tick_lab/README.txt.
Stage run-world.ps1, the release core, QDNativeWorld.dll, QDNativeLaunch.exe,
and a test profile under workspace/work/m31. Run with QD_WORLD_PLAYERS=1
and three guests. The test holds two local Pawn poses before each game
thread pump and verifies the stock mesh, disabled collision, unchanged
display identity, and both positions and yaws on the other three processes.
The last guest then stops sending. The remaining peers observe its
display hide and retire before all four stop and check their owned actors.
The runner verifies a clean exit, absence of UE4SS, and each save hash.
One guest uses offscreen D3D12 and the other three processes use NullRHI.
The summary records in-engine pump measurements and the per-slot poses.

This milestone covers player root transforms and a stock presentation.
Full movement and action animation, equipment and skins remain open.
The four-process run uses loopback. A separate Steam smoke test checks
the lobby tag and epoch through the production loader on one account.
